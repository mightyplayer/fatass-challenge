# Жиробас челлендж

Веб-приложение для соревнования друзей по похудению.

- **Админы** раз в неделю вносят результаты участников (вес, по желанию талию, комментарий и фото), задают стартовый вес и цель, переключают роли. Админом может быть и участник.
- **Супер-админ** (задаётся в `SUPERADMIN_TELEGRAM` через Telegram id или @username) назначает и снимает админов в `/admin`.
- **Участники** принимают или отклоняют оплаченные челленджи болельщиков, отмечают их выполнение (подтверждает админ), пишут посты с картинками.
- **Болельщики** выбирают фаворита (один постоянный голос, можно перенести или снять), ставят лайки на посты, отчёты и челленджи, бросают платные челленджи и донатят.
- **Дашборд** показывает динамику (процент сброшенного веса по неделям), турнирную таблицу, прогресс к цели, донаты и голоса.
- **Без входа** видно всё: дашборд, ленту, челленджи, страницы участников. Лайк, голос, донат или челлендж отправляют гостя на вход и возвращают обратно.
- **Вход** только через Telegram Login по OpenID Connect (Authorization Code + PKCE, проверка `id_token` по JWKS), без legacy-виджета.

Стек: Next.js 15 (App Router, server actions), PostgreSQL + Prisma, Tailwind 4, Recharts. Картинки хранятся на диске (docker volume) или в S3-совместимом хранилище.

## Локальный запуск с демоданными

Понадобятся Git, Node.js 22 или новее и Docker с Compose. Для просмотра демо Telegram не нужен.

```bash
git clone https://github.com/mightyplayer/fatass-challenge.git
cd fatass-challenge
cp .env.example .env
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.

Сгенерируйте пароль PostgreSQL и секрет подписи сессий. Команды выведут по одной строке.

```bash
node -e "console.log('POSTGRES_PASSWORD=' + require('node:crypto').randomBytes(24).toString('hex'))"
node -e "console.log('SESSION_SECRET=' + require('node:crypto').randomBytes(48).toString('hex'))"
```

Запишите значения в `.env`. Замените `REPLACE_ME` в `DATABASE_URL` тем же паролем PostgreSQL. Установите `APP_URL=http://localhost:3000` и `DEV_LOGIN=true`. Поля `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET` можно оставить пустыми.

Запустите только PostgreSQL, с доступом через локальный интерфейс.

```bash
docker compose -p fatass-challenge-dev run -d --name fatass-challenge-local-db -p 127.0.0.1:5432:5432 db
docker exec fatass-challenge-local-db pg_isready -h 127.0.0.1 -U slim -d slim
```

Когда `pg_isready` выведет `accepting connections`, установите зависимости, примените миграции и один раз загрузите демоданные.

```bash
npm ci
npm run db:migrate
npm run db:seed
npm run dev -- --hostname 127.0.0.1
```

Откройте `http://localhost:3000`. На главной появятся демо-участники и результаты. Для входа по имени откройте `http://localhost:3000/login`. В production вход по имени отключён.

Остановить базу можно командой `docker stop fatass-challenge-local-db`, снова запустить — `docker start fatass-challenge-local-db`. Если PostgreSQL у вас уже запущен, укажите в `DATABASE_URL` свою пустую базу и пропустите команды Docker для PostgreSQL.

## Запуск на сервере

На сервере понадобятся Git, Docker с Compose, домен с DNS-записью на сервер и доступные снаружи TCP-порты 80 и 443.

```bash
git clone https://github.com/mightyplayer/fatass-challenge.git
cd fatass-challenge
cp .env.example .env
```

Укажите в `.env` домен в `DOMAIN` и его HTTPS-адрес без завершающего слеша в `APP_URL`. Сгенерируйте `POSTGRES_PASSWORD` и `SESSION_SECRET` командами из раздела локального запуска. Их можно выполнить на любой машине с Node.js. Compose выставит `DATABASE_URL` внутри контейнера приложения. Оставьте `DEV_LOGIN=false`, настройте вход через Telegram и укажите Telegram ID или `@username` своего аккаунта в `SUPERADMIN_TELEGRAM`.

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app caddy
```

Compose поднимет PostgreSQL, приложение и Caddy. Caddy получит HTTPS-сертификат, а приложение применит миграции при старте. База и загруженные картинки сохраняются в томах `pgdata` и `uploads`. После входа через Telegram супер-админ может назначать админов на странице `/admin`.

### Вход через Telegram

1. В @BotFather откройте настройки бота и раздел **Login Widget**. Добавьте в Allowed URLs адрес сайта и URI `https://ваш-домен/api/auth/telegram/callback`.
2. Запишите Client ID и Client Secret в `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET` в `.env`.
3. Для подписи выберите RS256 или ES256.

## Правила и баллы

- **Старт** (`COMPETITION_START`, 12.10.2026): админ вносит стартовый вес и талию.
- **Недели 1–11** (каждый понедельник после старта): админ вносит вес, дни с 10 000+ шагов, дни с кардио 60+ минут, силовые 45+ минут и штрафы.
  - вес: % снижения от прошлого взвешивания `<0,3%` → 0, `<0,6%` → 3, `<0,9%` → 6, `<1,2%` → 9, иначе 12;
  - шаги, кардио, силовые: по баллу за день или тренировку, не больше 3 в каждом;
  - итог недели = сумма − штрафы.
- **Финал** (`COMPETITION_FINAL`, 31.12.2026): финальные вес и талия, недельных баллов не дают.
  - бонус за талию по % уменьшения от старта: `<1%` → 0, `<3%` → 2, `<5%` → 4, `<7%` → 6, `<9%` → 8, иначе 10;
  - ставки: каждый участник угадывает финальный вес остальных, ошибка до 1/2/3 кг даёт 3/2/1 балла. Ставки видны только автору до финала.
- Итог = вес + шаги + кардио + силовые − штрафы + ставки + талия. Правила в коде: `src/lib/scoring.ts`, проверки: `npm test`.

## Донаты

Ручной перевод без платёжки. Телефон для СБП и банк участника заполняет он сам в «Моём прогрессе» или админ во вкладке «Пользователи». Болельщик создаёт донат, видит реквизиты, переводит и жмёт «Я перевёл». Статусы: ждёт перевода → ожидает проверки → подтверждён админом или отклонён (болельщик может отменить до перевода). Публично видны только подтверждённые. Очередь проверки: `/admin?tab=donations`.

## Призовой фонд

Отдельно от донатов участникам. Супер-админ в `/admin?tab=fund` задаёт базовую сумму и назначает хранителя фонда из админов. Хранитель указывает свой телефон и банк для СБП. Болельщик на `/fund` создаёт взнос, переводит хранителю по СБП и жмёт «Я перевёл»; подтверждает или отклоняет взнос только хранитель. Статусы те же, что у донатов. Сумма фонда = база + подтверждённые взносы; она и список болельщиков с их взносами показаны на дашборде. Если снять с хранителя админку, хранитель и реквизиты сбрасываются.

## Доменная модель

| Сущность | Суть |
|---|---|
| `User` | Пользователь из Telegram. `role`: `PENDING` → `FAN` или `PARTICIPANT`; `isAdmin` ставит супер-админ; `sbpPhone`, `sbpBank` — реквизиты участника для донатов (`paymentDetails` — старые реквизиты одной строкой) |
| `WeeklyResult` | Результат участника за неделю (`week`: 0 — старт, 1..N — недели, N+1 — финал) с показателями активности и штрафом; `enteredById` — кто из админов внёс |
| `Prediction` | Ставка участника на финальный вес другого участника |
| `Challenge` | Платный челлендж от болельщика участнику. Вознаграждение идёт по СБП хранителю фонда: `AWAITING_PAYMENT → PAYMENT_REVIEW → PENDING/PAYMENT_REJECTED` (подтверждает хранитель), затем `PENDING → ACCEPTED/DECLINED`, `ACCEPTED → COMPLETION_REVIEW → COMPLETED/FAILED` (подтверждает админ). Автор может удалить челлендж до ответа участника: без оплаты он удаляется, с оплатой становится `CANCELLED`. Хранитель выплачивает вознаграждение за `COMPLETED` участнику и возвращает автору за `DECLINED/FAILED/CANCELLED` (`settledAt`) |
| `Donation` | Донат болельщика участнику с проверкой админом (`DonationStatus`) |
| `PrizeFund` | Призовой фонд (одна запись): базовая сумма, хранитель, телефон и банк для СБП |
| `FundContribution` | Взнос болельщика в призовой фонд с проверкой хранителем (`DonationStatus`) |
| `Vote` | Голос болельщика за фаворита, один на болельщика, без недельного сброса |
| `Post`, `PostImage` | Посты участников с текстом и до 6 картинок |
| `Like` | Лайк на пост, отчёт или челлендж (по одному от пользователя) |
